These layouts include remaining cut parts only. Parts are grouped into horizontal strips: dashed guides mark full-width crosscuts across the sheet, followed by cuts within each strip. Construction rules in this version

Cabinets may be frameless, face-frame overlay, or face-frame inset on a per-cabinet basis. Structural carcass joints use pocket screws in the supplied project defaults. Pure drawer cabinets use the hidden cabinet-box material and remain open-backed unless the cabinet row overrides the box/carcass species. Single-door cabinet boxes, shelves, and mixed/open visible cabinet parts default to the face/front material, and each cabinet row can override box/carcass and face/front species independently. Single-door applied backs match the door/front material. Face frames are modeled as solid-wood perimeter frames and are reported separately as linear stock. Drawer boxes use the drawer-box material with bottoms fitted completely between the four walls. Open spaces receive applied backs at the rear. Adjustable shelves are pin-supported; fixed mixed-cubby dividers are pocket-screwed. Countertops attach through top stretchers. No edge banding is included.

Toe-kick/base: each cabinet gets a separate 2"-high ladder frame using the hidden cabinet-box material, intended to use offcuts. A separate visible skin uses the cabinet's face/front material. The BOM treats adjacent cabinets with the same face/front species as one installed run and makes the skin in the longest pieces that fit the configured sheet length; SketchUp shows one skin segment per cabinet because the presentation model spaces cabinets apart.

CabinetDrafter Help

Cabinet planner · version 1.3.1

Quick start: choose inches or millimeters, edit the cabinet list, inspect the built-in 3D preview, check the sizing/BOM warnings, and save your project JSON. SketchUp export is optional.

1. What CabinetDrafter does

CabinetDrafter is a single-file local browser tool for designing cabinet runs using frameless or face-frame construction. It calculates drawer boxes, doors, open cubbies, shelf openings, plywood parts and sheet nesting, and renders the cabinet lineup directly in the page. SketchUp export is optional. It does not need a web server or an online account.

  • Build and reorder a lineup of drawer/mixed cabinets, single-door cabinets, and open-shelf cabinets.
  • Enter drawer box heights and open-space heights from bottom to top.
  • Use inches or millimeters without changing the underlying geometry.
  • Generate a plywood BOM, detailed cut-list CSV, remaining-work sheet-planning diagrams, and a shopping list that accounts for full sheets already on hand.
  • Orbit and inspect the cabinet model directly in the browser and save the current view as PNG.
  • Optionally generate a Ruby script that builds and saves the model in SketchUp Pro.
  • Save the project to JSON and keep a browser-local recovery copy automatically.

2. First-time workflow

  1. Choose units. Inches and millimeters are only display/entry choices; CabinetDrafter keeps canonical geometry in inches internally for SketchUp compatibility.
  2. Edit the Cabinets table. Set a label, type, width, quantity, vertical stack/opening heights, and shelf count where appropriate. Use the arrow buttons in the last column to reorder the run.
  3. Review the sizing preview. Fix anything shown as a warning before relying on the cut list.
  4. Review the BOM and sheet layouts. Grain-sensitive visible parts are kept oriented when Preserve visible grain direction is enabled.
  5. Click Save Project JSON. Pick a normal file such as my_kitchen.json. Supported browsers will then auto-save that same file as you edit.
  6. Click Download Ruby script. CabinetDrafter shows the exact load ... command to paste into SketchUp.
  7. In SketchUp Pro: open Extensions → Developer → Ruby Console, paste the command, and press Enter. By default, regenerating replaces the prior Generated Cabinet Lineup group; turn off that export option to keep prior generated cabinets.

4. Drawer / mixed stack syntax

The stack is always entered bottom → top.

Fixed cubby divider panels are pocket-screwed into the cabinet sides.

5. Open-shelf heights

For an Open shelf cabinet, use the same vertical-stack field to enter clear opening heights, bottom to top.

9.5, 12, auto

This creates three clear openings. The first two are fixed to the entered heights and the final/top opening uses the remaining height. Use auto only for the final opening. If the field is blank, the Shelves count is used and the shelves are spaced evenly.

These shelves are still adjustable shelf-pin shelves; the entered heights describe the modeled layout, not fixed pocket-screw locations.

6. Construction model

CabinetDrafter currently models the following construction system:

Face frames: select the front construction per cabinet. Global face-frame settings control stile width, rail width, frame thickness/material, overlay, and inset reveal. Frames are perimeter-only; intermediate rails between individual drawers/cubbies are a future enhancement.
  • Per-cabinet front construction: frameless, face-frame overlay, or face-frame inset.
  • Pocket-screw structural joinery.
  • Standard carcass: 3/4 plywood.
  • Drawer boxes: configurable 1/2 plywood sides, front, back, and bottom.
  • Drawer bottom fits completely between the four drawer walls; no dado or rabbet.
  • Drawer slide clearance: 1/2 per side / 1 total by default.
  • Cabinet rows can override box/carcass plywood and face/front plywood species independently.
  • Drawer fronts and doors: 3/4 face/front plywood by default; sizing follows the selected frameless/face-frame front style.
  • Current 1/16 side reveal produces 11/16 geometric overlap on a 3/4 carcass edge and a 1/8 seam between adjacent cabinet fronts.
  • Single doors use two concealed Euro-style hinges. Hinge drilling dimensions are not generated until a hinge model is chosen.
  • Adjustable shelves use shelf pins. Fixed mixed-cubby dividers use pocket screws.
  • Countertops attach with screws through the flat top stretchers.
  • No edge banding or solid-wood edge treatment is currently included.

7. Built-in 3D preview

The 3D Preview is completely local and does not require SketchUp. It is generated from the same cabinet dimensions used by the BOM and cut list.

  • Drag to orbit around the cabinets.
  • Use the mouse wheel to zoom.
  • Shift-drag to pan.
  • Use Front, Left, Right, Top, or Isometric for preset views.
  • Turn fronts/doors, drawer boxes, or backs on and off to inspect construction.
  • Use Hidden-line print style for black-and-white shop printouts.
  • Click Save PNG to save the current view as an image.

The browser preview can use flat birch/cherry colors or a white/light-gray hidden-line style with black visible edges. It is intended as a construction/design view, not a photorealistic renderer.

8. 3D / SketchUp labels

Each label type can be switched on or off independently:

  • Cabinet summary labels.
  • Cabinet width labels.
  • Drawer box heights.
  • Drawer face heights.
  • Open-space heights for mixed cubbies and open-shelf openings.

Cabinet width labels are short overall-width notes centered near the front bottom of each cabinet. Drawer/opening height numbers are placed directly in the visual center of the corresponding face/opening. Inch labels use practical fractions rounded to the nearest 1/16; metric labels use millimeters.

9. Saving projects

CabinetDrafter uses two layers of local saving:

  • Browser recovery copy: every edit is stored in browser local storage.
  • Project JSON: click Save Project JSON once and choose a file. When the browser permits direct file access, CabinetDrafter auto-saves that file after edits and before Ruby export/copy.

Use Save Project As… to branch a design. Use Export JSON copy for a portable snapshot. Use Load / Import JSON to open somebody else's project.

10. Build progress and inventory

Use the Build progress section while cutting and assembling. Assembly checkboxes let you mark a whole carcass, toe-kick/base, drawer, door, or shelf set complete while still saving progress as individual physical plywood part IDs. Each cabinet and assembly row lists the generated material species so you can see what to build from without opening every cut part. Checking work complete keeps the cabinet in the design and 3D model, but removes those physical parts from the remaining-work nesting and remaining cut-list CSV.

Full sheets on hand are tracked by material. They mean full, uncut usable sheets only; scraps and partial sheets are not counted as full sheets in this version. Remaining layout sheets can be selected individually before printing, and part rectangles use black-and-white species hatch fills instead of color coding.

11. Sharing CabinetDrafter

To give the tool to somebody else, send the CabinetDrafter ZIP. They can unzip it and open index.html directly in a modern browser. To share a specific design, send the project JSON too.

12. BOM, face-frame stock, and sheet layouts

The sheet optimizer is a guillotine-friendly planning aid for breaking down sheets into rectangular strips. Dashed guides show full-width crosscuts between strips. It accounts for the configured sheet size, edge trim, saw kerf, and visible grain direction. Inspect real sheets for damage, voids, and grain before cutting, and choose a cut order that keeps each panel supported.

Current run assumption: CabinetDrafter treats the complete cabinet list as one installed straight run when it creates the continuous visible-material toe-kick skin. If cabinet face/front species changes within the list, it splits the skin into adjacent same-species runs. If a project contains cabinets on multiple walls or separate runs, split them into separate project files or manually split the toe-kick skin until multi-run support is added.

13. Before you cut

  • Confirm actual plywood thickness; nominal 3/4 and 1/2 sheet goods may measure less.
  • Confirm drawer-slide side clearance before cutting drawer boxes. The default is 1/2 per side.
  • Choose the actual concealed hinge before boring door cups or mounting-plate holes.
  • Confirm countertop overhangs and wall conditions separately; CabinetDrafter currently models cabinets, not room walls/counters.
  • Review every warning in the sizing/BOM section.
  • Treat the generated cut list as a verified plan only after checking a representative cabinet against your real hardware/materials.

14. Current limitations

  • One global cabinet height and depth for the whole project.
  • Only single-door cabinets; no paired/double-door cabinet type yet.
  • No fillers, scribes, applied finished end panels, corner cabinets, or room/wall layout.
  • No hardware BOM yet for slides, hinges, shelf pins, pocket screws, or installation fasteners.
  • No automatic hinge cup-bore or shelf-pin drilling templates.
  • No explicit multiple cabinet runs/walls; continuous toe-kick skin assumes one run.
  • No edge treatment or pull drilling because those choices are still intentionally TBD.

15. Troubleshooting

The SketchUp model did not change: use the exact timestamped Ruby filename and load command CabinetDrafter shows after downloading. With the replace option enabled, each generated script removes the old Generated Cabinet Lineup group before rebuilding it. With the option disabled, the script adds a new timestamped group instead.

Project JSON is not auto-saving: browsers may require write permission again after reopening a local HTML file. Click Save Project JSON to reconnect the remembered file. Use Save Project As… only when you want to choose a different destination. Browser recovery storage continues to work independently.

An open-shelf height list does not fit: use auto for the top opening, or adjust the entered clear heights so the total plus shelf thicknesses fits the available vertical space.
